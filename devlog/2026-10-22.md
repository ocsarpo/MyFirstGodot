# 2026-10-22 - Day 9

오늘은 실행 직후 바로 플레이되던 게임에 시작 화면을 추가했다. 문서의 구조와 설정은 현재 `main.gd`, `main.tscn`을 기준으로 정리했다.

## 오늘 만든 것과 이유

CanvasLayer 아래에 StartScreen(Control), CenterContainer, VBoxContainer, TitleLabel, StartButton을 추가했다. Full Rect로 화면 영역을 채우고 제목 `MY FIRST GODOT`과 START 버튼을 중앙에 세로로 배치했다.

사용자가 시작하기 전에 Player와 Enemy가 움직이지 않도록 Main의 `_ready()`에서 SceneTree를 Pause했다. Pause 중에도 시작 입력을 받을 수 있게 **StartButton만 When Paused**로 설정했다. StartScreen 전체의 Process Mode를 바꾼 것은 아니다.

StartButton의 `pressed` Signal을 Main에 연결했다. 클릭하면 StartScreen의 Alpha를 0.25초 동안 0으로 줄이는 Tween을 실행한다. 이 Tween에 `TWEEN_PAUSE_PROCESS`를 지정해 게임이 Pause된 동안에도 전환이 진행되도록 했다. Tween 종료를 기다린 뒤 StartScreen을 숨기고 Pause를 해제한다.

## 달라진 게임 흐름

```text
실행 → Pause 상태의 시작 화면 → START → 0.25초 Fade Out
→ 시작 화면 숨김·Pause 해제 → 플레이·획득·점수
→ Enemy 충돌 → 사망 연출 → GAME OVER
→ R로 Scene Reload → 다시 시작 화면
```

현재 변경은 `main.gd`와 `main.tscn`이다. 직접 작성한 코드와 Scene은 문서 작업 중 수정하지 않았다. UI 구조·Pause·Signal·Tween의 역할은 [기본 UI 문서](../docs/11-basic-ui.md)에 정리했다.

## 10월 남은 목표 — 미구현 계획

### PC Web / Mobile Web 대응

PC 키보드와 모바일 터치 입력, 모바일에서 조작할 수 있는 START·RESTART UI, 화면 비율과 UI 배치 대응을 준비한다. 하나의 Web build를 PC와 모바일 브라우저에서 모두 플레이할 수 있게 하는 것이 목표다. 현재 모바일 대응을 완료한 것은 아니다.

### Stage 구성

실제 플레이용 맵, Stage Clear와 다음 Stage 전환, Stage별 Enemy 수 증가를 검토한다. Stage에 따라 Player 수도 늘리고 여러 Player를 같은 입력으로 동시에 조작하는 방식을 핵심 게임 아이디어 후보로 생각하고 있다. 구체적인 규칙은 확정하거나 구현하지 않았다.

### 디자인 구성

기본 아이콘 위주의 Player·Enemy·Item 비주얼을 교체하고 맵과 UI에 시각적 통일감을 준다. 시작 화면·Stage Clear·Game Over 등의 연출을 정리하고 필요하면 최소 효과음을 추가한다. 기존에 만든 사망·Game Over 피드백 외의 추가 디자인 작업은 계획이다.

### 이번 달 완성 기준

START부터 마지막 Stage까지 한 게임의 흐름을 완성하고, PC·모바일 웹에서 모두 플레이할 수 있게 한다. 최소한의 게임다운 디자인과 피드백을 갖춘 뒤 Godot Web Export와 itch.io 등의 배포를 통해 URL로 플레이하게 만드는 것이 최종 목표다. **Web Export와 itch.io 배포는 아직 수행하지 않았다.**

## 오늘의 핵심

게임 전체를 Pause하되 시작 버튼의 입력과 전환 Tween은 별도로 실행하도록 설정했다. UI 전환이 끝난 뒤 Pause를 해제해 플레이 시작 시점을 연결했다.
