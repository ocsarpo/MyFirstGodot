# 2026-10-23 - Day 10

## 1차 작업 — PC / 모바일 입력 공통화

모바일 이동 입력을 테스트하고 키보드 없이도 Restart할 수 있는 UI를 추가했다. 이번 기록은 실제 코드와 Scene에서 확인한 첫 번째 개발 세션의 상태다.

### 진행한 내용

- CanvasLayer 아래 MobileControls를 Full Rect로 추가했다. Mouse Filter는 Ignore로 설정해 빈 Control 영역이 다른 UI 입력을 가로막지 않게 했다.
- 상하좌우 Button의 `button_down`과 `button_up`을 Main에 연결했다. `Input.action_press()`와 `Input.action_release()`로 기존 `move_left/right/up/down`을 활성화·해제한다.
- Player의 이동 코드는 그대로 유지했다. 키보드와 화면 버튼이 같은 Input Action을 거쳐 기존 `Input.get_vector()`에 연결된다.
- CanvasLayer에 RestartButton을 추가했다. 실행 시 숨기고 GAME OVER 처리에서 표시하며, `pressed`가 현재 Scene을 다시 로드한다. PC의 R 키 재시작도 유지했다. 두 방식 모두 재로드 후 시작 화면으로 돌아간다.
- Scene의 Item5 위치가 `(169, 779)`에서 `(120, 1002)`로 바뀐 내용도 함께 저장했다.

### 확인한 개념과 현재 범위

입력 장치를 게임의 행동과 분리하면 같은 이동 로직을 재사용할 수 있다. 이동 버튼은 누름과 해제를 각각 처리하고, 재시작 버튼은 클릭을 처리한다. 자세한 개념은 [Input Map](../docs/06-input-map.md)과 [기본 UI](../docs/11-basic-ui.md)에 정리했다.

상하좌우 화면 버튼은 모바일 조작 구조 검증용 임시 UI다. 최종 모바일 컨트롤은 확정하지 않았으며, 다음 세션의 가상 조이스틱 등은 계획일 뿐 아직 작업하지 않았다. 이번에는 직접 만든 `main.gd`, `main.tscn` 변경을 보존하고 문서만 추가·갱신했다.

## 2차 작업 — VirtualJoystick과 PC / Mobile Web 테스트

실제 시각은 10월 24일 새벽이지만 사용자 기준 10월 23일의 두 번째 개발 세션으로 기록한다. 아래 설정은 실제 파일을, 브라우저에서의 동작과 설치 경험은 사용자의 테스트 기록을 기준으로 한다.

### 입력 구조와 실제 설정

- 임시 방향 Button 4개와 Signal 연결을 제거하고 MobileControls 아래 VirtualJoystick을 Full Rect로 추가했다. `joystick_mode = 1`인 Dynamic 방식으로 터치한 위치에서 드래그하여 이동한다.
- 네 방향은 기존 `move_*` Action에 연결했다. Player와 Main 스크립트는 이번 diff에서 변경되지 않았으며, 예전 버튼 처리 함수는 Main에 남아 있다.
- `joystick_size = 150.0`, `tip_size = 75.0`, `visibility_mode = 1`을 저장했다. 마우스→터치 에뮬레이션은 켜고 터치→마우스 에뮬레이션은 껐다.
- Camera Zoom의 0.6 설정을 제거해 기본값 1.0을 사용한다. 기준 해상도 1280×720과 `canvas_items`는 유지하고 Aspect의 `expand` 설정을 제거해 기본값 `keep`으로 비율을 유지한다.
- START 최소 크기 269×90·글꼴 32, RESTART 최소 크기 269×89·글꼴 30, Score Label 글꼴 42로 조절했다. Item8 위치 변경 `(1282, 740)` → `(1386, 959)`도 포함됐다.

### Web 실행과 실제 기기 확인

Web preset과 Export Template을 준비하고 One-click Deploy로 PC 브라우저 실행을 확인했다. 실제 휴대폰 Chrome에서도 START, 이동·획득, GAME OVER, RESTART를 확인했다. PC 마우스 터치 에뮬레이션과 휴대폰 손가락 입력을 모두 시험했다.

같은 네트워크의 모바일 접속을 위해 Web HTTP Host를 `0.0.0.0`으로 바인딩하고 TLS와 PC LAN IPv4를 사용했다. 로컬 URL 형태는 `https://<PC IPv4>:8060/tmp_js_export.html`이었다. Safari에서는 로컬 self-signed TLS 환경의 접속 문제가 있어, 정상 HTTPS 배포 후 별도 검증하기로 했다. Safari 미지원으로 결론 내리지 않는다.

휴대폰에서는 PC에서 보던 월드와 UI가 작고 비율도 달랐다. Sprite를 직접 확대하는 대신 Camera Zoom을 조정하고, Stretch와 UI 크기를 따로 맞췄다. 실제 기기로 확인해야 가독성과 터치 크기의 차이를 알 수 있었다.

Web preset은 Desktop·Mobile VRAM 압축을 모두 활성화했고, 프로젝트의 ETC2/ASTC import도 활성화했다. 생성된 `build/web/` 산출물은 로컬에 유지하고 Git에서는 제외했다. 자세한 설정과 테스트 구분은 [Web Export 문서](../docs/14-web-export-and-testing.md)에 정리했다.

### 이번 체크포인트의 범위

PC / Mobile Web 입력과 로컬 실행의 기본 뼈대를 검증했다. Stage·Stage Clear·Enemy/Player 수 증가·여러 Player 동시 조작·최종 디자인·최종 사운드는 아직 구현하지 않았다. itch.io 배포와 실제 배포 환경 Safari 검증도 다음 단계다. 문서 정리 중 게임 코드·Scene·Project·Export 설정을 추가로 수정하지 않았다.
