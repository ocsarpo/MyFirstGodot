## 이번 주 목표와 결과

## 이번 주 완성된 게임 흐름

```text
Player 이동 → Item 획득·Score와 시각적 피드백
→ Enemy 추적·충돌 → Player 사망·이동 중단
→ Sprite 사망 Tween → died Signal → GAME OVER 등장
→ R 입력 → Scene Reload → 다시 플레이
```

현재 R 재시작은 GAME OVER UI 연출 시작부터 가능하다. 시작 화면, 사운드, 새 판 시작 연출은 아직 없다.

## 배운 핵심 개념

- 게임 느낌을 조절할 값은 이름을 가진 디자인 파라미터로 두고 `@export`로 노출할 수 있다.
- 반복 충돌과 연출 중 재접촉은 `is_dead`, `collected` 같은 상태로 중복 처리를 막는다.
- Signal로 Player 상태와 Main의 UI 처리를 연결하고, `await`로 연출 완료 후 알림을 보낼 수 있다.
- Tween은 scale뿐 아니라 Alpha도 바꿀 수 있다. 실제 대상 Node와 확대 기준점이 결과를 좌우한다.
- 공통 Item 스크립트 한 번의 수정이 여러 Instance에 적용되며, 각 Instance는 랜덤 시차를 독립적으로 갖는다.
- 카메라의 시야·Zoom과 타일의 이동 제한은 서로 다른 역할이다.

## 시행착오

접촉 중 충돌 로그가 반복되어 사망 처리를 한 번만 실행할 상태가 필요했다. 획득 연출로 Item이 잠시 남게 되자 중복 획득도 막아야 했다.

Score Tween을 복사하면서 대상을 `self`로 남겨 Main 전체가 확대됐다. 이후에는 Item 루트, Sprite2D, Label 중 무엇을 바꾸려는지 확인했다. GAME OVER는 Label의 중앙 pivot을 설정해 확대 기준도 조절했다.

## 게임이 어떻게 달라졌는가

한 번 실패한 뒤 다시 플레이할 수 있게 되었고, Item 획득·점수 변화·사망이 단순한 값 변경을 넘어 시각적으로 드러나기 시작했다. 기능 테스트 공간에서 작은 게임 형태로 넘어가는 중이다.

월 1게임의 완성 기준도 기능 동작에 더해 득점·사망·시작과 재시작의 느낌, 기본적인 시각적 통일감, 주요 행동의 시각 또는 사운드 피드백을 포함하는 방향으로 잡았다. 현재 완료한 피드백과 앞으로 필요한 연출은 구분한다.
